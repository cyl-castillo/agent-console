# CLI Integration Watch — Claude Code & Codex

Documento vivo: qué superficies de los CLIs usa Agent Console, qué cambió upstream y
qué mejoras quedan por aplicar. Lo mantiene la tarea recurrente diaria `cli-integration-watch`
(scheduled task de Claude Code): cada corrida chequea versiones nuevas, agrega hallazgos al
backlog y aplica UNA mejora (PR, nunca merge/release sin OK de Carlos).

## Backlog priorizado

### Quick wins (candidatos para la mejora diaria)

- [ ] **W1 — Hook exec-form `args` (Claude 2.1.139)**: reemplaza nuestro workaround `node "<path>"` (PR #109) por `{command, args: [path]}` sin shell. CUIDADO compat: versiones <2.1.122 invalidan settings.json entero ante entradas que no entienden → gatear por versión detectada (`claude --version`) o esperar adopción. Codex: quoting Windows arreglado en 0.145 con el formato actual.
- [x] **W2 — Auth detección estructurada** (PR #139, 2026-08-06): `claude auth status --json` → `claude_cli::auth_status()` (probe acotado a 8s, `None` = "no sé", nunca "deslogueado"); `exit_error` y `engine_runner::finish` nombran la expiración aunque el CLI culpe a otra cosa; "Fix Claude login" usa `claude auth login` cuando el probe prueba que el subcomando existe, con fallback a `claude` pelado. Queda como opcional: mostrar cuenta/método en la GUI (el comando IPC `claude_auth_status` ya los devuelve).
- [x] **W3 — `sessionTitle` writeback** (PR #149, 2026-08-18): el endpoint de inyección devuelve además `sessionTitle` = el nombre que la sidebar muestra para esa terminal, y el bridge lo eco-devuelve como `hookSpecificOutput.sessionTitle` → el mismo nombre aparece en `/resume` y `claude agents`. Regla: viaja lo que la sidebar muestra (rename manual, semilla de ticket Jira, o el auto-nombre silencioso `deriveSessionLabel`); los `shell N` por defecto NO salen, así que mientras la consola no tenga nada mejor el CLI conserva su propio título autogenerado. Dedupe por terminal (se manda una vez y de nuevo solo si cambia) para no pisar un `/rename` tipeado dentro del CLI. Campo ignorado por versiones viejas y por Codex (seguro). Limitación conocida: viaja solo en prompts que ya consultan el endpoint (≥12 chars, sin `/` inicial) — no agregamos latencia a prompts cortos por un título.
- [x] **W4 — `last_assistant_message` en Stop (Claude 2.1.47)** (PR #150, 2026-08-19): el bridge Stop guarda las palabras de cierre del agente (`summary` + `summaryTruncated`, cap 1000 chars, trim) y el turn_end del ledger las lleva junto al diff — el turno cierra con lo que el agente DICE que hizo al lado de la evidencia de lo que cambió. Segundo guard en Rust (`truncate_chars`) por si el script en disco es de un install viejo. Ausente ⇒ el evento es idéntico al de antes (Codex hoy no lo manda; tolerado por campo faltante, no por versión). El resumen se ve en el timeline de proof y entra en la review pre-firma (redactable como cualquier otro campo). Siguen abiertos, sobre este mismo dato: resumen hablado fin-de-turno (hito 3 de voz) y digest sin parsear jsonl.
- [ ] **W5 — Trust de workspace**: hooks NO corren en directorios no confiados (Claude 2.1.3/2.1.51/2.1.218) → detectar y avisar en la GUI en vez de asumir que el hook disparó (hoy el fallo es silencioso; misma clase de bug que el de Windows/Melissa). **BLOQUEADO por señal rota (2026-08-25, PR #148 frenado en verificación)**: `~/.claude.json → hasTrustDialogAccepted:false` coexiste con hooks funcionando (verificado con 2.1.241 en teams-translator: eventos, approvals, Stop y sessionTitle, todo dispara) — el campo ya no codifica el trust real. Para retomar: experimento controlado en dir fresco para encontrar el marcador actual de Claude; el lado Codex (`config.toml → trust_level`) sí parece fiable. El branch `feat/cli-watch-workspace-trust` queda rebaseado con gates verdes; detalle en el comentario del PR.

### Medianas

- [ ] **M1 — `claude agents --json` (2.1.145)**: fuente nativa de sesiones vivas (id, cwd, estado) para el sidebar — complementa/reemplaza la captura por hook.
- [x] **M2 — `StopFailure` hook (Claude 2.1.78)** (PR #169, 2026-08-27): Claude dispara `StopFailure` EN LUGAR de `Stop` cuando la API rechaza el turno, así que hasta ahora ese turno no cerraba nunca — el ledger lo dejaba abierto, la píldora de estado seguía "trabajando" hasta que vencía el decay, y el motivo solo existía como texto que pasaba de largo en la terminal. Nuevo bridge (`stopfailure-hook.cjs` + modo `stopfailure` del binario nativo) que escribe un evento `turn_failed` con el enum `error` del CLI (pasado VERBATIM: un valor que este build no conoce igual tiene que llegar a la UI), `error_details` acotado a 1000 chars y el `last_assistant_message`. En Rust cierra el turno por la MISMA rama que `turn_end`, así que el diff pre/post se calcula igual: el timeline dice "este turno murió, y esto es lo que había cambiado hasta ahí". En la UI: `markIdle()` + toast de error persistente que nombra la causa, y apunta a "Fix Claude login" solo cuando loguearse de nuevo lo arregla (`authentication_failed`, `oauth_org_not_allowed`) — no en `account_on_hold` ni `billing_error`, donde ese click no sirve. **Solo Claude**: el evento y su enum son de Claude, Codex no tiene equivalente. Auto-instalado con marker propio (`.stopfailure-autoinstalled`), clase observador: el CLI ignora su salida y su exit code, y las versiones viejas simplemente nunca disparan un evento que no tienen. Modo de bridge distinto de `stop` a propósito: comparten binario, y el modo es también cómo install/uninstall reconocen NUESTRA entrada.
- [ ] **M3 — SessionEnd hook de Codex (0.145)**: señal de teardown que hoy no tenemos del lado Codex.
- [ ] **M4 — Approvals headless (Claude 2.1.85/2.1.89)**: PreToolUse `"defer"` + `AskUserQuestion` vía `updatedInput` → camino real a approvals con UI propia en sesiones headless (scheduler/advisor).
- [ ] **M7 — Hook `Interrupt` de Codex (0.150)**: nuevo evento que corre cuando se interrumpe un turno top-level (puede llamar comandos o handlers MCP). Es el gemelo Codex de lo que `StopFailure` resuelve del lado Claude: hoy un turno interrumpido en Codex tampoco cierra el turno del ledger. Evaluar junto con M3 (SessionEnd de Codex) — un solo bridge de "el turno terminó sin Stop" para los dos motores.
- [x] **M8 — `PostModelSwitch` (Claude 2.1.251)** (PR de hoy, 2026-08-31): hasta ahora el modelo de una sesión era solo INTENCIÓN — "lo último que pedimos" — y el propio `modelStore` lo decía en su comentario de cabecera: *"never the agent's actually-loaded model"*. Diverge de tres formas, todas silenciosas: el usuario tipea `/model` dentro de la terminal; nuestro propio push de `/model` (el pill) solo prende si el agente está idle en el prompt; y Claude cambia de modelo por su cuenta (fallback, restaurar al resumir). Y la mentira tiene dientes: ese valor viejo es el que `buildLaunch` clava con `--model` en el próximo `--resume`, o sea que un pill desactualizado ARRASTRA la sesión de vuelta al modelo equivocado. `PostModelSwitch` es la primera señal que dice qué corre de verdad. Nuevo bridge (`modelswitch-hook.cjs` + modo `modelswitch`) → evento `model_switch` con `to_model`/`from_model`. Dos filtros en el bridge: `agent_id` presente ⇒ es un subagente cambiando SU modelo, no dice nada de la sesión (sin esto, un `Task` reescribía el pill); y sin `to_model` no hay nada que reportar. La regla de reconciliación (`reconcileSwitchedModel`, testeada) es lo delicado: misma familia (`opus` vs `claude-opus-5`) ⇒ NO tocar, porque cambiar el alias por el id pinnearía la sesión a una release concreta en el próximo resume; familia distinta ⇒ adoptar el preset (`haiku`), así el pill dice "Haiku" y `--model haiku` resume al mismo lugar; modelo sin preset conocido ⇒ el id verbatim (mejor un nombre desconocido que uno familiar y falso). Un nombre que no pasa `isValidModel` se descarta entero: el evento viene de un archivo world-writable, misma regla que los session ids. Sin `termId` que matchee NO hay fallback a la terminal activa (a diferencia del hook de prompt): escribir el modelo de otra sesión sobre la que está en foco sería peor que no saber. **Solo Claude** (Codex no tiene el evento; el mapeo canónico→preset vive en el perfil como `matchModelPreset`, ausente en Codex, así que sus presets de *effort* nunca se matchean contra nombres de modelo). Marker propio `.modelswitch-autoinstalled`; evento async ⇒ el CLI ni lee nuestros campos de decisión, y las versiones viejas simplemente nunca lo disparan (el pill sigue mostrando intención, como antes).
- [ ] **M6 — Hooks asíncronos de Codex (0.148)**: los command hooks pueden correr async (y llamar tools MCP); `hooks list` ahora expone el execution mode. Nuestros 4 bridges son spawns sincrónicos de node en el camino del prompt → async saca esa latencia del lado Codex. Se pisa con S2 (HTTP hooks): decidir un solo camino de transporte antes de tocar el instalador.
- [x] **M5 — Hyperlinks OSC 8 en el terminal** (PR #170, 2026-08-28): la pregunta era si xterm los degrada bien. NO: sin `linkHandler` configurado, xterm abre un `confirm("…WARNING: This link could potentially be dangerous")` nativo y después llama `window.open()`, que el webview de Tauri bloquea → el click era "diálogo feo, y después nada". Ahora el handler es nuestro: `safeTerminalUrl` acepta solo `http(s)` (parseado con `new URL`, no regex) y el link se abre en el navegador real vía `plugin-opener` — nunca dentro del webview, que navegaría la consola fuera de sí misma. Al pasar el mouse se muestra el destino en un chip junto al cursor (`pointer-events:none`, no puede robarle el click al link que describe), y un esquema no-http avisa por toast en vez de fallar en silencio. `allowNonHttpProtocols` queda en false (xterm ni nos ofrece `javascript:`/`file:`); `safeTerminalUrl` es el segundo cinturón porque ese default es de xterm, no nuestro. Lo habilita Codex 0.150 (labels de markdown clicables) y lo usa Claude para links de docs/PR. **Pendiente aparte**: URLs planas (las de `claude`/`codex login`, por ejemplo) NO son links — eso requiere `@xterm/addon-web-links`, o sea una dependencia nueva; queda como candidato del backlog, no lo decide la tarea diaria.
- [ ] **M5b — URLs planas clicables**: `@xterm/addon-web-links` (oficial, misma familia que `addon-fit`) haría clicable el URL de OAuth que imprime `claude`/`codex login`, que hoy hay que seleccionar y copiar a mano. Es una dependencia nueva → decisión de Carlos. El handler de M5 ya sirve de destino común.

### Vigilar (sin acción aún)

- **Salida de hooks ahora estricta (2.1.248)**: un stdout que empieza con `{…}` pero NO es JSON válido pasó de tratarse como texto plano a reportarse como error de hook con el mensaje de parseo; y un `PreToolUse` que imprime una respuesta inválida ahora nombra el hook y el error de schema en `claude agents` en vez de dejar la sesión esperando en silencio. Nuestros bridges serializan con `serde_json`/`JSON.stringify` y el de aprobaciones emite `{}` cuando no decide, así que estamos del lado correcto — pero cualquier `print!`/`console.log` suelto en un bridge ahora es un error VISIBLE. Regla: los bridges no escriben a stdout salvo su respuesta.
- Output gigante de un hook ya no puede tumbar la sesión con "Prompt is too long" (2.1.247), y los caps nuestros (1000 chars) siguen siendo la primera línea de defensa.
- `sessionTitle` (W3) más robusto upstream: los títulos custom ya no desaparecen de `/resume` después de ~64 KB de conversación (2.1.239). Sin acción.
- Hooks con el cwd borrado ya no fallan con `posix_spawn ENOENT` — corren desde la raíz del proyecto o el home (2.1.239). Toca a nuestras sesiones de worktree descartado; sin acción.
- Codex 0.150: markdown links como labels clicables en terminales que lo soportan — más insumo para M5 (OSC 8 en xterm).
- Codex 0.150: proyectos no confiados ya no aportan `AGENTS.md` de proyecto. Refuerza que del lado Codex el trust sí es una señal real (ver W5).
- Codex 0.149/0.150: `codex agents` (dashboard de sesiones), `codex queue` (mandar mensajes a sesiones vivas) y auto-títulos de tareas sin nombre + `/rename` con sugerencia. Los dos primeros son el gemelo Codex de M1; el tercero se pisa con W3 (nuestro `sessionTitle` no viaja a Codex, y ahora Codex se autonombra solo).
- `PreModelSwitch` (2.1.251): el gemelo bloqueante de M8 — puede DENEGAR un cambio de modelo (`permissionDecision`), y su timeout bloquea. No lo instalamos: hoy no tenemos ninguna política que justifique vetar un `/model` del usuario, y un hook que puede colgar el switch es exactamente la clase de cosa que no se auto-instala. Candidato solo si alguna vez hay "modelo fijado por proyecto/rol".
- `SessionStart` en resume ahora recibe staleness de la sesión + costo estimado de re-cachear (2.1.251): hoy no usamos SessionStart, pero es el dato que haría honesto un "esta sesión está fría" antes de resumir. Junto con `source:"fork"` (2.1.214), la razón acumulada para adoptar el evento.
- Codex 0.151: MCP (grace period configurable para servers opcionales, extensiones que interceptan resultados de tools), sandbox remoto, catálogos de plugins y fixes de Guardian. Nada toca nuestras superficies.
- Codex SQLite thread store (experimental 0.145/0.146): dirección anunciada para reemplazar rollouts JSONL — si se vuelve default, cambia cómo se capturan/resumen sesiones.
- Claude npm deprecado como método de install (2.1.15): binario nativo será la norma; revisar docs/onboarding que mencionen `npm install`.
- `codex login --api-key` hard-deprecado (usamos `codex login` interactivo — OK).
- SessionStart `source:"fork"` (2.1.214): hoy no usamos SessionStart; relevante si lo adoptamos.
- Matchers de hooks: hyphens exact-match (2.1.195), comma matchers (2.1.191) — nuestros hooks no usan matchers con guiones; re-verificar si agregamos.
- Binarios de codex ahora se sirven desde `releases.openai.com`/R2 con fallback GitHub (0.146).
- `ANTHROPIC_DEFAULT_MODEL` (2.1.236): fija el modelo de sesiones nuevas sin pisar un `/model` del usuario, a diferencia de `ANTHROPIC_MODEL`. Hoy pasamos `--model <m>` explícito por sesión (sigue siendo lo correcto); relevante si alguna vez queremos un default de proyecto blando.
- SIGTERM en modo print/SDK ya no registra turno interrumpido ni denials sintéticos, y sigue saliendo 143 (2.1.237): nuestro cancel de headless (`engine_runner`) queda más limpio en el transcript; verificar que seguimos tratando 143 como cancelación y no como fallo.
- `codex exec fork` (0.148): forkear una sesión desde headless — candidato para roundtable/worktrees, que hoy arrancan sesiones vacías.
- Codex 0.148 restaura cwd y approval policy persistidos al resumir: nuestro `codex resume <id>` hereda el estado correcto sin que le pasemos nada.

## Protocolo de la tarea diaria

1. `npm view @anthropic-ai/claude-code version` y `npm view @openai/codex version`; comparar contra baseline. Si hay versión nueva: leer el delta del changelog (Claude: `raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md`; Codex: releases de `openai/codex`) y agregar al backlog lo que toque nuestras superficies.
2. Elegir UNA mejora desbloqueada (prioridad: breaking > quick win > mediana). Implementarla en branch `feat/cli-watch-<slug>`, con tests, gates verdes (`cargo fmt --check`, `clippy -D warnings`, `cargo test`, `npm run build`, `npm run format:check`).
3. Abrir PR (nunca mergear, nunca releasear — eso lo decide Carlos tras probar en GUI).
4. Actualizar este archivo (baseline, checkbox, historial) dentro del mismo PR.
5. Si no hay nada accionable: actualizar solo "Última revisión" y terminar barato.
